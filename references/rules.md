# 报销核验与编排规则

## 0. 本地资料边界

- 默认输入是用户已下载的本地文件或文件夹。收到本地路径后递归扫描、分类、读取和核验，不登录携程，不从网站下载、查询或打印订单。
- 网页逐单打印属于可选能力，每次必须由用户在当前任务明确提出；不沿用历史授权。
- 原始资料只读。解压、标注、重命名、顺序调整和合并均在新的工作目录或输出文件中完成。
- 文件名只用于初步索引，最终类型和归属以文件内容为准。资料不完时先完成可确定部分，将缺件和无法判定项列入问题清单。

## 1. 费用分摊与工作请示

- 工作请示中的分摊表区分机票费用和住宿费用；仅有一种费用时只生成对应分摊。
- 以消费明细序号作为归属主键，按费用划分表中的公司/项目顺序和序号区间汇总。机票资料提供机型或项目字段时，同时按现行表口径填写；不得从姓名自行推断公司或项目。
- 每项记录序号范围、金额和小计，最终合计应与明细、用款申请及发票一致。
- 明细中所有退票人员均进入退票说明，逐人写明姓名、订单/票号、金额和退票原因。来源没有原因时写“原始资料未载明，待补充”，禁止编造。

## 2. 携程酒店与审批单

- 出差单按住宿消费明细的序号排序，在右上角标注与明细一致的序号。
- 出差起止日期必须完整包含入店日和离店日；出差地点必须包含酒店所在城市。允许出差范围更宽，但不能遗漏实际住宿日期或城市。
- 出差流程中列有同行人时，按明细核对同行人，并在同一出差单标注其对应序号。多人共用一张审批时只附一次，记录全部对应序号。
- 因接待需要订酒店的，必须匹配对外接待申请单。申请日期须覆盖入店和离店日期，批准房间数量须与报销明细一致。
- 无法唯一匹配审批单时列为待确认，不能用日期相近的单据强行对应。

## 3. 住宿标准与超标审批

- 按有效出差制度核对入住人姓名、岗位/级别、入住城市、可报标准、晚数/房间数和明细实付金额。
- 以制度明确的计价口径判断是否超标；制度按“人/晚”“间/晚”或特殊城市档位计算时分别处理，不擅自换算。
- 超标必须提供住宿超标申请表，且应有董事长签批。缺申请、缺签批或签批日期不合理均列为异常。
- 没有制度或人员级别表时，不输出“未超标”结论，只写“无法判定，待补制度/级别资料”。

## 4. 酒店订单详情

- 先按明细订单号精确匹配，再按费用划分表的公司顺序和明细序号排列；人员、城市、日期和金额用于复核。
- 当前业务口径：资料包只纳入持卡人为赵乐的订单详情；与李波相关且来源材料中没有订单详情的序号可空开。空开的序号仍须保留在主控清单，状态写“按规则空开/订单详情未提供”，不得拿其他订单补位。
- 同一订单覆盖多人或多条明细时，详情页只放一次，置于该订单最早序号处，并在清单记录覆盖的全部序号。
- 订单详情为多页时保持完整连续。订单号不一致时，即使姓名和金额相近也不能视为匹配。

## 5. 发票及打印份数

- 核对购方、销售方、发票类型、号码、开票日期、项目、税额、价税合计和报销总额。
- 增值税专用发票需打印两份。电子交付时生成两份相同的发票打印页或单独的“两份打印版”，不得修改发票内容；普通发票保留一份。
- 多张发票按费用划分表的公司顺序排列；无法拆分到公司的公共发票置于资料包末尾，并在清单注明覆盖的序号或金额范围。

## 6. 排序键与问题清单

默认排序键为：

1. 文档区段（公共申请/明细、公司证据、发票）；
2. 费用划分表中的公司顺序；
3. 数字序号；
4. 同一资料内部原页序。

问题清单至少包含：`序号`、`公司/项目`、`人员`、`问题类型`、`发现`、`所需补件/处理`、`证据文件及页码`、`状态`。将“确实缺失”“按既定规则空开”“无法判定”区分记录。
